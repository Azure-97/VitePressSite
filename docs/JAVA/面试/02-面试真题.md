## 4.[单选]执行以下程序后的输出结果是（）

```java
public class Test {
    public static void main(String[] args) {
        StringBuffer a = new StringBuffer( "A");
        StringBuffer b = new StringBuffer( "B");
        operator(a , b);
        System .out .println(a + "," + b);
     }
     public static void operator(StringBuffer x , StringBuffer y) {
         x .append(y);
         y = x;
      } 
}
```

(A) A,A

(B) A,B

(C) AB,AB

**(D) AB,B**

> 1. 首先，在`main`方法中，创建了两个`StringBuffer`对象`a`和`b`，并分别初始化为"A"和"B"。
> 2. 然后，调用`operator`方法，并将`a`和`b`作为参数传递。
> 3. 在`operator`方法中，`x.append(y)`将`y`（即`b`）的值追加到`x`（即`a`）中，因此`a`变为"AB"。
> 4. 接着，`y = x;`将`x`（即`a`）的引用赋给`y`（即`b`），因此`b`现在引用`a`，即指向了`StringBuffer`对象"AB"。
> 5. 最后，在`main`方法中，`System.out.println(a + "," + b);`会输出`a`和`b`的当前值。由于`a`是"AB"，而`b`也指向了"AB"这个`StringBuffer`对象，所以输出是"AB,B"。

## 10[单选]下列关于ConfigurationProperties 注解的说法中，正确的是（）

**(A) @ConfigurationProperties 注解只能作用于类**

(B) 使用@ConfigurationProperties 注解为Bean注入属性时，必须为Bean设置setter方法

(C) @ConfigurationProperties 注解必须和@Component结合使用

(D) 要想使@ConfigurationProperties 注解注入的属性生效，必须使用@EnableConfigurationProperties注解开启注入

> (A) @ConfigurationProperties 注解只能作用于类
> 这个说法不完全准确。虽然通常情况下@ConfigurationProperties是作用于类级别的，但它也可以作用于特定的方法上，不过这种用法较少见。
> (B) 使用@ConfigurationProperties 注解为Bean注入属性时，必须为Bean设置setter方法
> 这个说法基本正确，因为默认情况下@ConfigurationProperties是通过setter方法注入属性的，但是它也支持构造器注入。因此，如果使用默认的setter注入方式，则确实需要setter方法。
> (C) @ConfigurationProperties 注解必须和@Component结合使用
> 这个说法不准确。@ConfigurationProperties注解并不一定要与@Component一起使用。实际上，为了确保配置类能够被Spring容器管理，通常会使用@Component或@Configuration等注解。但是，也可以通过其他方式如@EnableConfigurationProperties或者直接在配置类中使用@Bean方法来注册@ConfigurationProperties标注的类。
> (D) 要想使@ConfigurationProperties 注解注入的属性生效，必须使用@EnableConfigurationProperties注解开启注入
> 这个说法是正确的。@EnableConfigurationProperties注解用于启用@ConfigurationProperties的自动配置功能，确保带有@ConfigurationProperties注解的类能够被正确地加载并注入相应的属性。如果没有显式地使用@EnableConfigurationProperties，那么可以通过在@Configuration类中使用@Bean方法返回@ConfigurationProperties标注的类实例来实现类似的功能。

## 14[多选]已知 String a = "a"; String b = "b"; String c = a+b; String d = new String("ab"); 以下操作结果为true的是（）

**(A) (a+b).equals(c)**

(B) (a+b)==c

(C) c==d

**(D) c.equals(d)**

> 当您执行`String c = a + b;`时，这实际上是在编译时期被优化为`String c = "ab";`。然而，这个优化并不总是发生。特别是当使用变量进行字符串连接时，编译器可能无法确定在运行时这些变量将具有什么值，因此它可能会生成一个新的字符串对象。在这种情况下，`c`是一个在堆内存中创建的新字符串对象，而不是字符串常量池中的"ab"。
>
> 另一方面，`String d = "ab";`直接引用了字符串常量池中的"ab"。
>
> 因此，即使`c`和`d`的内容相同，它们指向的内存位置不同：`c`指向堆内存中的新对象，而`d`指向字符串常量池中的对象。这就是为什么`c == d`输出`false`的原因。`==`运算符比较的是引用地址，而不是字符串内容。如果您想要比较字符串内容是否相同，应该使用`equals()`方法

## 17[简答题]

简述sleep和wait方法的异同点

> ### 相同点：
>
> 1. **暂停执行**：`sleep`和`wait`方法都可以使当前执行的线程暂停执行，进入等待状态。
> 2. **释放CPU资源**：在这两种方法被调用时，当前线程都会让出CPU，给其他线程执行的机会。
>
> ### 不同点：
>
> #### 1. 定义位置和方法归属：
>
> - **sleep**：
>   - `sleep`是`Thread`类的一个静态方法，即`Thread.sleep(long millis)`。
>   - 不需要持有任何锁。
> - **wait**：
>   - `wait`是`Object`类的一个实例方法，即`object.wait()`。
>   - 必须在同步代码块中调用，当前线程必须持有该对象的监视器锁。
>
> #### 2. 暂停时间：
>
> - **sleep**：
>   - `sleep`方法指定了线程暂停执行的精确时间（毫秒为单位）。
> - **wait**：
>   - `wait`方法可以指定超时时间，也可以不指定，不指定时线程将无限期等待，直到被其他线程通过`notify`或`notifyAll`方法唤醒。
>
> #### 3. 锁的处理：
>
> - **sleep**：
>   - 调用`sleep`方法不会释放当前线程所持有的任何锁。
> - **wait**：
>   - 调用`wait`方法时，当前线程会释放它所持有的监视器锁，允许其他线程进入同步块或方法。
>
> #### 4. 唤醒机制：
>
> - **sleep**：
>   - `sleep`方法让线程休眠指定时间后，线程会自动醒来，不需要其他线程干预。
> - **wait**：
>   - `wait`方法使线程进入等待状态，直到其他线程调用相同对象的`notify`或`notifyAll`方法将其唤醒。
>
> #### 5. 异常处理：
>
> - **sleep**：
>   - 如果线程在休眠期间被中断，`sleep`方法会抛出`InterruptedException`。
> - **wait**：
>   - `wait`方法在等待期间被中断，也会抛出`InterruptedException`，但是调用`wait`方法需要处理`InterruptedException`，因为它发生在同步代码块中。
>
> ### 总结
>
> `sleep`和`wait`方法都可以用来暂停线程，但它们在使用上有明显的不同。`sleep`用于线程自己控制暂停时间，而`wait`用于线程间的通信，需要配合锁和同步机制使用。选择哪一个方法取决于线程控制和通信的具体需求。

## 18[简答题]

简述TCP和UDP之间的区别

> 区别：
>
> 1. **连接性**：
>    - **TCP**：面向连接的协议。在数据传输之前，**需要建立连接**，传输完成后需要断开连接。
>    - **UDP**：无连接的协议。发送数据之前**不需要建立连接**，数据可以直接发送给接收方。
> 2. **可靠性**：
>    - **TCP**：提供**可靠**的传输。通过序列号、确认应答、重传机制等确保数据的正确性和完整性。
>    - **UDP**：**不保证可靠性**。数据可能会丢失或重复，且不提供错误恢复。
> 3. **数据流控制**：
>    - **TCP**：具**有流量控制功能**，可以根据接收方的处理能力调整发送速率，避免网络拥塞。
>    - **UDP**：**没有流量控制**，数据以应用程序生成的速度发送，可能会导致数据丢失。
> 4. **数据传输方式**：
>    - **TCP**：面向**字节流**，数据被视为一连串无结构的字节流。
>    - **UDP**：面向**数据报**，保留消息边界，每个数据报都是一个独立的信息单元。
> 5. **速度和效率**：
>    - **TCP**：由于建立连接和保证数据可靠性的机制，**速度较慢**。
>    - **UDP**：无需建立连接和可靠性检查，**速度较快**。
> 6. **使用场景**：
>    - **TCP**：适用于对数据准确性要求较高的应用，如网页浏览、文件传输、电子邮件等。
>    - **UDP**：适用于对实时性要求较高的应用，如视频会议、在线游戏、实时数据传输等。
>
> 总的来说，TCP提供了一种可靠、有序的数据传输方式，但速度较慢；而UDP提供了一种快速但不保证可靠性的数据传输方式。

## **19[简答题]**

现有注册用户表table_user，有两个字段：user_id(用户id)、reg_tm(注册日期)。有订单表table_order,有三个字段：order_id(订单号)、order_tm(下单日期)、user_id(用户id)。注：所有日期格式均为yyyy-MM-dd。 请写出“查询2024年1月1日至今，注册当天即下单且当天订单数量≥2的用户id”的SQL语句 编写实现该查询的SQL语句

```sql
SELECT tu.user_id
FROM table_user tu
JOIN (
    SELECT to1.user_id, to1.order_tm, COUNT(*) as order_count
    FROM table_order to1
    WHERE to1.order_tm >= '2024-01-01'
    GROUP BY to1.user_id, to1.order_tm
    HAVING COUNT(*) >= 2
) to2 ON tu.user_id = to2.user_id AND tu.reg_tm = to2.order_tm
WHERE tu.reg_tm >= '2024-01-01';
```

## 20[简答题]

分布式架构下，Session共享有哪些方案？

> 在分布式架构下，Session共享的方案主要包括以下几种：
>
> 1. **数据库Session共享**：将Session信息存储在数据库中，所有服务器都可以访问这个数据库，从而实现Session共享。
> 2. **缓存服务器Session共享**：使用如Redis、Memcached等缓存服务器来存储Session信息。这种方式读写速度快，性能好，适用于大型分布式系统。
> 3. **Cookie Session共享**：将Session信息存储在客户端的Cookie中。这种方式减轻了服务器的负担，但安全性相对较低，且受限于Cookie的大小限制。
> 4. **基于Token的Session共享**：使用Token（如JWT）来代替传统Session，Token中包含用户信息，服务器无需存储Session，只需验证Token的有效性。
> 5. **分布式Session管理**：使用专门的分布式Session管理组件，如Spring Session，它提供了对分布式Session的支持，可以透明地集成到应用中。
